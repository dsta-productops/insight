## 2026-08-06 — detailed per-mode saved recap (DESIGN EXPLORATION, no code shipped)

Alvin asked whether the saved-session summary should be **more detailed and tailored per mode**, positioning the live one as an **"active summary"** to deconflict the level-of-detail difference. This was a discussion — **nothing was built, nothing is locked.** Where we landed (full detail in memory `insight-detailed-saved-recap-design.md`):

**Direction:** split the current single summarizer (`lib/summary/index.ts`, one mode-agnostic prompt shared by live + regen) into TWO artifacts:
- **Live "active summary"** — stays terse (6 bullets, <12 words), glanceable, incremental, GPU-contended with the coach, no speaker attribution. Unchanged.
- **Saved "detailed recap"** — post-session, untimed, no coach contention → can be richer, attributed (once the labeling pass runs), and per-mode shaped.

**Hard constraint (Alvin's call): everything stays on the packaged 8B — NO premium provider.** Richer output is earned by architecture (more passes on the untimed offline path), not a better model.

**Simulated on the bundled 8B** (llama.cpp `:8080`, Q4_K_M, n_ctx=4096) against real focus-group session `932eafe1` (packaged data dir, table-discussion, 40.5 min / 664 segs, unlabeled), via map-reduce (MAP = extract bullets per ~40-seg window; REDUCE = organize):
- Flat 4-bucket reduce (Topics/Consensus/Disagreement/Examples) → ~20 lines, **too brief for 40 min**, and consensus/disagreement were the model GUESSING (no attribution) — unsafe.
- Topic-clustered reduce (5–8 themes, points nested, "keep detail, merge only true dupes") → **8 themes / 62 points, genuinely usable.** Same ~2.5 min wall-clock (map ~87s + reduce ~61s). **Depth is nearly free** — MAP cost is identical either way and is already paid live incrementally; only REDUCE output tokens grow. Insight: if the live session PERSISTS per-window extractions, the saved recap is just the ~60s reduce.
- 8B gotcha seen: 2 of 17 windows looped → 0 bullets, burned the token cap. Cap MAP output ~250 tok + add a retry/skip guard.

**Three rules that govern every mode's recap:**
1. **Recap, never verdict** — no scores/hire-no-hire/diagnosis/"the participant seems…". Synthesis is the coach's job; interpretation is the practitioner's. Protects the additive invariant AND keeps the 8B safe.
2. **Topic/theme-clustering is the safe default shape** (holds depth, fully extractive).
3. **Any section naming a speaker ROLE is GATED behind attribution** — surfaces only when the transcript text explicitly names it, or a labeling pass ran. The 8B must never guess who spoke. Covers consensus/disagreement, action-item owners, quote attribution. **Panel "audience questions" was RETRACTED** for exactly this (can't tell audience vs panelist vs moderator; the current labeler is binary/2-role and can't separate a panel's many roles anyway — that's the deferred live-attribution track).

**Per-mode recap skeletons proposed** (all extractive; only two break the theme-clustered mould):
- **Research** (user-research, defence-psych): themes + pain points/needs + notable quotes. Defence-psych = factual record, NOT assessment.
- **Job interview**: background + evidence-by-theme (STAR examples) + candidate's questions; NO scoring, nothing on protected characteristics (mirror the coach fairness rule).
- **Staff dialogue**: topics + concerns + commitments + follow-ups.
- **Counselling: INVERTS "detailed" → minimal + strictly factual** (topics, stated concerns/goals, agreed next steps). Highest governance; richness here becomes illegal assessment.
- **Meeting: the standout DIFFERENT shape → decisions + action items (+owner/date only when spoken) minutes.**
- **Table-discussion/focus-group**: themes + notable examples; consensus/disagreement gated behind labeling.
- **Panel**: threads + key points + notable exchanges + source-neutral questions.

**Next step queued (generation side):** validate the two odd-shaped templates on the 8B against real sessions — **meeting** (decisions/actions) and **job-interview** (evidence-by-theme). The theme-clustered six are effectively proven. Then write up the decoupled-saved-recap design (naming: live = "active summary"; keep "recap" wording on both as an anti-synthesis guardrail).

## Multi-mode expansion — direction decided 2026-08-05 (4 of 8 modes built)

Alvin wants to extend INSIGHT beyond user-research interviews into a **family of live-conversation modes on the same engine**. Transcription, RAG, the throttled coach, the running summary, and export are all domain-neutral; what's mode-specific is a thin layer — coach corpus, glossary, framing/copy, and coach *output modality*. Full rationale in memory `insight-multi-mode-expansion.md`. Decisions locked in the discussion:

**Canonical structure: 8 modes, 3 families, 6 axes, 4 invariants.** A "mode" is NOT a code path — it's a declarative **profile over 6 axes** that dials the fixed engine. Families are an internal grouping for build-sequencing + code reuse; the operator only ever picks a single *mode*, and the app must not sprawl into 8 products (protects the low-cognitive-load invariant).

- **Families → modes:**
  - **Research interviewing** (1:1, low power-asymmetry, technique-driven): user research *(built)*, defence-psych research interview.
  - **Consequential 1:1** (power-asymmetric, higher stakes, the additive/untrained safety contract is load-bearing): job interview, staff dialogue, counselling.
  - **Multi-party facilitation** (capture + airtime/flow, low stakes, live speaker attribution is the hard part): meetings, table discussion / focus group, panel moderation.
- **The 6 axes a profile sets:** (1) party structure (1:1 / small-group / panel+audience), (2) coach corpus (domain technique menu / SYSTEM prompt), (3) coach output style (scripted read-aloud `ask` / soft meta-guidance / facilitation nudge), (4) stakes & safety framing (low→high), (5) retention default (persist / ephemeral-default / public-moot), (6) capture emphasis (insights / decisions+actions / assessment notes / minimal). **Two axes carry all the real risk — party structure (live speaker awareness, which today's architecture defers to a post-session labeling pass) and coach corpus/output (consequential domain content); the other four are cheap config.**
- **The 4 invariants (a profile can't override them):** purely additive, untrained operator, offline/local, low cognitive load.
- **Alvin's build priority** (reach, not technical adjacency): (1) **job interviews**, (2) **staff dialogues**, (3) **counselling**, (4) **meetings**, (5) **defence-psych**. Build one reference mode per family (job interview → consequential 1:1; meeting → facilitation); siblings (table discussion, panel moderation, defence-psych) are then mostly corpus+framing on top. The facilitation family forces the one genuinely new prerequisite — **live speaker attribution** (possibly satisfiable by a lighter signal: turn-taking / a per-speaker talk-time meter, rather than full live diarization, which the locked decision says Whisper can't do live without downgrading the model).
- **Operators are assumed UNtrained** — the primary constraint, applies from mode #1. The coach supplies competence a layperson lacks.
- **Purely additive posture** (deliberately chosen over an inhibitory guardrail). The coach only ever *offers* (question / definition / context / technique prompt); it NEVER vetoes. Why: additive error is cheap and symmetric, so the free/local 8B stays adequate (no safety-critical classifier, no premium-provider tension, no legal sign-off blocker on the corpus, existing Now-card UI unchanged), and it's more defensible with untrained users (no safety claim to over-rely on). **Explicit contract: operator + org protocol are the safety layer; INSIGHT is a companion, not a catch.** Steer softly by *crowding out* (surface a good question at a risky moment, don't block the bad one). Output modality varies by mode — verbatim read-aloud `ask` for job interviews; softer meta-guidance for counselling (never hand a layperson scripted clinical probes).
- **Ephemeral recording toggle.** A "don't save" mode: transcription still runs live in-memory (coach works), but on session end NOTHING persists — no audio, no transcript, no suggestion log. Pitch: "nothing is saved, nothing leaves this laptop" (processing is already fully local; the toggle governs *retention*). Governance caveat: a record is sometimes required, sometimes forbidden — who may flip it, and when, is per-mode policy, not just a switch.

## Transcription gotcha — cross-chunk Whisper loop (fixed 2026-08-05)

On silent/unclear audio (e.g. a panelist off-mic) Whisper hallucinates by echoing its conditioning prompt (the transcript tail), producing the SAME line on chunk after chunk — a real panel session flooded ~108s (13 chunks) with "Luis, what are you seeing from the private sector?". The existing guards only caught within-chunk loops (`collapseRepeatedPhrases`) and stock silence phrases (`HALLUCINATIONS`). Fix in `app/api/sessions/live/[id]/route.ts` POST: a **consecutive-duplicate guard** — normalize each new segment and drop it if it equals the previous kept line (seeded from the last stored segment via `readTranscript`, so cross-chunk loops collapse to one line). Applies to all modes; ephemeral seeds from "" (within-batch only). Root cause is audio capture (off-mic speaker) — this contains the symptom, it cannot recover uncaptured words. Costs one extra `readTranscript` per chunk (negligible for the single-operator local app).

| Free/local stack is the default; hosted providers are env-var swaps | Alvin's #1 preference. See stack table above. |

| **Silent chunks are dropped client-side** + hallucination blacklist server-side | Whisper `large-v3` emits "Thank you." on silence (training artifact). Two-layer fix: don't send speechless chunks; drop stock phrases whose *entire* text is a known hallucination (`app/api/sessions/live/[id]/route.ts`). |
| **Whisper conditioning prompt** = glossary vocab + transcript tail | Spells domain acronyms (PRD, CONOPS) correctly and keeps continuity across live chunks. `lib/transcribe/prompt.ts`. |
| Coach shows **one suggestion at a time** ("Now" card), newest wins, older collapse into "Earlier suggestions" | Low cognitive load. Not a scrolling feed. |
| Coach cards lead with a **verbatim question** (`ask` field) the researcher reads aloud; only a small "why · source" line beneath | Actionable > descriptive. The redundant `body` paraphrase line was removed on Alvin's request. |
| **Instant glossary definitions** bypass the LLM | On first mention of a glossary term, the definition is pushed to the Now card deterministically (regex match), no ~20 s LLM wait. Once per term per session. |
| Coach loop is **throttled** (`SUGGEST_INTERVAL_MS = 8000` in `/live`), context trimmed (5 chunks, 500 chars each), model pinned (`keep_alive: 30m`) | Latency profile (measured, warm pinned model): prompt-eval ~0.2 s, so **generation dominates** — ~4 s for ~85 output tokens at ~22 tok/s. (The old "prompt-eval dominates" note is stale; don't trim the prompt to chase speed — cut *output* tokens instead.) Output was trimmed by making coach `body` empty (the UI shows `ask`, never a coach `body`) and forcing terse `source` slugs: ~123 → ~85 tokens, ~5.5 s → ~4 s. With ~4 s passes the throttle was lowered 15 s → 8 s (Alvin chose max responsiveness; local Ollama has no quota). Anti-repeat means tighter passes surface the right nudge sooner, not more card churn. |
| **Aggressive anti-repeat**, all suggestion types | Echo filter (stemmed content-word containment, `lib/suggest/index.ts`) drops asks that re-cover questions already asked in the window or already shown this session; definitions dedupe on the acronym itself. Client sends full shown-content as the `exclude` list. Muting a legit follow-up is better than repeating the researcher. |
| Coach technique menu is an **ordered top-down decision list** in the system prompt (`lib/suggest/index.ts` SYSTEM) | The 8B model conflates the 7 techniques. A flat menu wasn't enough — on noisy real windows it defaulted to **critical-incident-technique**, which swallowed five-whys and satisficing (CIT's old trigger keyed on hedge words like "usually"/"I guess", which appear in almost every answer). Fix: a numbered decision order — neutral → five-whys → satisficing → laddering → contrastive → **CIT (the fallback, reached only after ruling 1–5 out)** → silence — plus "hedge words alone do NOT indicate a technique". Verified against live Ollama: messy five-whys/satisficing windows now resolve correctly (were 100% CIT); CIT recall preserved on genuine hypotheticals. Confirmed: injecting the CIT doc flipped even a clean laddering case to CIT. Document + glossary chunks still ground `context`/`definition` suggestions. |

### Apply the code-review findings

A post-Step-5 `/code-review` (8 finder angles + per-candidate verification) surfaced 8 findings. **#1 is now fixed (2026-07-25); the rest remain open.** Ranked:

1. **Label truncation (high, CONFIRMED) — ✅ FIXED 2026-07-25.** `lib/transcribe/label.ts` ran one LLM call over the whole transcript capped at `num_predict: 2048`, so transcripts past ~130–145 segments (a normal 30–60 min interview) truncated mid-array, `parseLabels` returned `[]`, and **the whole pass yielded zero labels while the route still stamped `labeledAt` and returned 200**. Fix applied: `labelSpeakers` now labels in fixed 40-line batches (`BATCH_SIZE`), sequential, lines numbered by global index so results map straight back; if the entire pass produces zero labels it **throws** (route → 500) instead of silently succeeding, and a batch-0 provider error (Ollama down / missing key) surfaces immediately. Partial success still saves. Verified end-to-end against a synthetic 150-segment transcript on live Ollama: 150/150 labeled, correct researcher/participant split, ~81 s over 4 batches. `num_predict` left at 2048 — always ample for ≤40 lines now.
2. **Retrieval topK crowding (high, CONFIRMED)** — `generateSuggestions` filters coach chunks *after* `retrieve(query, 5)` slices top-5. Coach chunks are 25 of ~41 store chunks (glossary is now 15 after the CLARA removal) and semantically closest to interview transcripts, so they eat the slots and get discarded, starving document/glossary context. Fix at depth: add a `sourceTypes` filter param to `retrieve()` (lib/rag/retrieve.ts) applied before ranking/slicing.
3. **Label route missing live guard (CONFIRMED)** — `POST /api/sessions/[id]/label` never checks session status (compare `app/api/sessions/live/[id]/route.ts:53`). Labeling a still-live session (direct URL / second tab) is a lost-update race against `appendSegments` (unlocked full-file rewrites) and leaves a stale `labeledAt` over unlabeled tail segments. Fix: 409 on `status === "live"`.
